## 今回修正した問題

- 初期描画が後続スクリプトの診断関数を直接呼び、読み込み順とスコープの違いで停止する問題。採集記録・図鑑・クエストの通常描画を診断パネルから独立させた。
- タブ切替が `main` 内のすべての `section` を隠していた問題。画面直下の section のみ切り替える。
- マップの非同期ジオコーディングが旧フィルターの結果を新しいレイヤーに追加する競合。世代番号とレイヤー参照で破棄する。ブロック・非表示の投稿も除外する。
- ガチャの300枚超の所持カード切り捨て。今後の抽選では所持を保持する。既に失われた履歴を復元するものではない。
- 無料ログインボーナス保存失敗後のメモリー上の残高加算。保存失敗時は元の状態に戻す。
- ガチャ図鑑、ランキング、フォロワー数のアカウント切替時の更新。プロフィールの端末内保存をアカウント別にし、古い問い合わせ結果の上書きを防ぐ。旧共通プロフィールはゲスト用に保持し、他人のアカウントに自動移行しない。
- Supabaseの認証コールバック内で認証関連APIを await して停止する恐れ。コールバック後に遅延して実行する。
- iOSビルドの `cap add ios` が既存のSwiftファイル用フォルダと衝突する問題。実際のXcodeプロジェクトをコミットし、以後 `cap sync ios` で同期する。
- ログインと地図の初期化がCDNのJavaScript読み込みに依存する問題。固定版Supabase/Leafletをアプリに同梱する。地図タイル・認証・投稿には引き続きネット接続が必要。
- 現在地の地図表示時にも第三者の地図タイルに通信することを画面に明記。ランキングは端末データによる未検証の参考値であることを明記。

## 課金の状態

**購入は無効。正式公開・Sandbox検証完了を意味しない。**

`ios/App/App/MushiverseCoinStore.swift` に固定の `purchasesEnabled = false` があり、購入メソッド自体が拒否する。Webの購入ボタンも無効。Capacitorプラグインはログインしたユーザー用のネイティブショップを表示するが購入できない。

サーバー検証の候補コードはApple公式 `@apple/app-store-server-library` を使用する。署名・証明書チェーン・オンライン証明書確認に加え、bundle ID、環境、商品、Consumable、数量、購入者UUID、購入日時、失効を確認する。Appleのサーバーから最新の取引を取得して再検証してからv2 RPCを呼ぶ。単にJWSをdecodeしただけでは付与しない。`APPLE_COIN_CREDIT_ENABLED` が `true` でなければ503で停止する。

**Edge FunctionとSQL候補は本番未適用。** 既存DBの3引数RPCを、リポジトリにある4引数RPCで置換していない。`supabase/sql/coin-wallet-v2.sql` は調査した本番スキーマ向けのアップグレード候補で、ステージングで適用・比較する必要がある。旧 `supabase/migrations/20261028_gacha_coin_wallet.sql` を本番へ盲目的に適用しない。

v2の付与は同一取引・同一ユーザー・同一商品・同一環境の再送だけ成功扱いとし、残高は増やさない。消費は残高ロック・結果保存を同じDBトランザクション内で実施する。商品種別とカードIDの対応も一致させる。旧クライアントの無料コインと購入コインは別管理。

未完了: 課金APIのステージング統合、購入コイン消費用Edge FunctionとUIの接続、Apple Sandboxで有効な署名・OCSPを含む実行確認、返金通知/消費済みコインの取り扱い、レート制限、同時リクエストの複数接続試験、削除済みユーザーの既存JWTでの再試行確認。これらを終えるまで両方の停止スイッチを維持する。

## 検証と限界

- `npm run verify:web`: Webバンドル一致、61本のインラインJS構文、課金停止の静的チェック。
- `npm test`: Apple検証後のポリシー15ケースと、PGliteによる実Postgresエンジンでの付与・消費・重複・権限・残高不足・結果整合性試験。
- `npm run test:e2e`: iPhone相当の390×844表示で、6タブ、週間クエスト/記録描画、300枚超のガチャ、保存失敗、アカウント切替、通信復帰。Supabase応答はモック。実サービスへの投稿や実機試験ではない。
- `npx deno check --no-config --node-modules-dir=manual supabase/functions/credit-apple-gacha-coins/index.ts`: Edge Function型検証。
- `npm run ios:sync && npm run ios:check`: ローカル資産とiOS構成確認。Xcodeコンパイル・署名とは別。
- GitHub Actionsの初回Web CI成功を確認。WebKitプロジェクトも追加したが、ローカル環境ではOS共有ライブラリ不足で起動不可。CIで依存をインストールして実行する。macOSシミュレータビルドは結果を別途確認する。
- npm audit: ランタイム依存には指摘なし。Capacitor CLIのxcode/uuid経由で中程度の指摘が残る（開発/ビルド依存）。修正済みとは扱わない。
- Supabase本番は読み取り調査のみ。全publicテーブルでRLS有効。moderator用SECURITY DEFINER RPCは認証済みユーザーに実行権があるが、本体でmoderator_accountsの照合あり。アドバイザー警告を「無条件公開」とは断定しない。
- Supabaseの漏洩パスワード保護が無効。ダッシュボードで有効化可否を確認する。

## iPhoneから本人にしかできないこと

1. Apple Developerの本人確認、契約・有料App契約、税務/銀行口座情報を完了する。
2. App Store ConnectでBundle ID `com.rikuto.mushiverse` を確認し、Consumable商品 `mushiverse.coins.100` / `.550` / `.1200` を設定する。価格・販売地域・商品審査情報は本人が確認する。
3. App Store Connect APIキーの権限を確認し、GitHubリポジトリのSettings → Secrets and variables → Actionsに `ASC_KEY_ID`、`ASC_ISSUER_ID`、`ASC_API_KEY_P8_BASE64` を登録する。秘密鍵をソース・Issue・チャットへ貼らない。既に登録済みなら値を再送する必要はない。
4. Apple検証用の鍵・公式ルート証明書・Appの数値IDをSupabaseのSecretsに設定する。詳細は `docs/APPLE_BACKEND_SETUP.md`。サーバー停止スイッチは有効化しない。
5. ストアの正式な運営者表示とプライバシー申告、スクリーンショット、レビュー用アカウントを確定する。
6. 署名ビルド配布後、iPhoneのTestFlightでカメラ・権限拒否・写真・地図・アカウント切替・削除・Sandbox購入を試す。

Macを購入する前提にはしない。コンパイル/アーカイブはGitHubのmacOSランナーで実施する。既存署名ワークフローは手動起動で、TestFlightへのアップロードはまだ提供しない。現在のAppIcon/SplashはCapacitorテンプレートなので、そのまま申請しない。
